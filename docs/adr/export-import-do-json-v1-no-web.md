# Export/import do JSON v1 no web: leitor próprio, abertura relaxada e prova cruzada

- Contexto: o CLI fechou o ciclo do JSON v1 na ENG-9 ([Export/import do JSON v1](export-import-do-json-v1.md)) — escritor e leitor em `apps/cli/src/model/`. O web chegou à ENG-19 com persistência IndexedDB e as telas de fila, lista, check-in e stats, mas sem o caminho que leva o dado do navegador para o CLI e de volta. O `docs/especificacao/WEB.md` já reserva a rota `#/data` para `RF-18`/`RF-19`/`RNF-07`, e o `MODELO-DE-DADOS.md` fixa o contrato JSON v1. Quatro decisões não estavam tomadas: onde mora o leitor, como o export sobrevive a um banco fora do contrato, como o DOM do download fica fora do codec e como provar que o arquivo de um lado abre no outro.
- Decisão: o **leitor mora no web**, em `apps/web/src/features/data/model/` (`json.ts`, `migrations.ts`, `merge.ts`), com a borda assíncrona em `controller/service.ts`, espelhando `apps/cli/src/model/json.ts` e `import.ts` **sem importar o CLI**. O `packages/core` fica intocado: ele não recebe API de browser/Node e o `Date.parse` da comparação de conflito é decisão da borda. O web não reimplementa `RN-nn`; só reusa o contrato fixado.
- Decisão: o **codec não carrega pt-BR**. O `strings.test.ts` varre `src/**` (exceto `strings.ts` e `store/`) procurando caractere não-ASCII e texto JSX solto, então o model lança erros tipados — `InvalidDumpError` e `UnsupportedSchemaError` (a versão) — e o controller os traduz para `strings.data.*` (`arquivo inválido`, `schema_version N não suportado`). Sem isso, a mensagem do `WEB.md` teria que viver no model e furaria a varredura.
- Decisão: **download e escolha de arquivo ficam atrás de `FileGateway`** (`apps/web/src/files.ts`, zona root), com `saveFile(name, content)` e `pickFile()`. O adaptador `browserFiles` é o único ponto que toca `Blob`, `URL.createObjectURL`, `<a download>` e `<input type="file">`; o `App` recebe `files` por injeção, como já recebe `store` e `deps`, e os testes injetam um duplo. O codec e o model seguem sem DOM, preservando as zonas do `architecture.test.ts`.
- Decisão: **`RNF-07` vira abertura relaxada, usada só na recuperação.** `openStore` ganha `options.checkSchema` (padrão `true`); com `false` ele pula o `assertSchema` e devolve a porta. A recusa do ADR de persistência continua na abertura normal; quando o boot falha por `SchemaVersionError`/`SchemaMismatchError`, a tela de falha oferece o download, que lê o banco pela abertura relaxada. IndexedDB ilegível, sem versão divergente, não exporta — mostra `não foi possível exportar o arquivo`, porque o arquivo baixado antes é a saída, não uma exportação pela metade.
- Decisão: **o merge é idêntico ao ADR do CLI**: arquivo vence só com `updated_at` (item) ou `cold_archived_at` (arquivo morto) estritamente mais novo, comparado por instante (`Date.parse`); `review_log` insere só se o `id` não existe, com dedup dentro do arquivo; `cold_archive` reconstrói `{item, review_logs}` do snapshot achatado; o import é aditivo, nunca espelho. `review_log` órfão e `schema_version` futuro recusam o **arquivo inteiro**, e toda a escrita roda numa única `store.transaction` com a validação antes da primeira gravação. `meta` grava só as quatro chaves conhecidas (`cold_archive_after_days`, `locale`, `streak_current`, `streak_last_day`), nunca `schema_version` nem `last_cold_archive_export_at`.
- Decisão: a rota nova é **`#/data`**, com item de navegação e uma tela que cobre os quatro estados do `WEB.md`; as contagens do export e do import aparecem na confirmação, vindas do retorno de `exportDump`/`importDump`. Isso atualiza explicitamente `routing.test.ts` e `app.test.tsx`, que pinavam seis rotas.
- Decisão: o **teste cruzado mora em `tests/export-import-cross.test.ts`** (projeto `scaffold`, ambiente node) e faz o round-trip real nas duas direções: dump gerado pelo store do web aplicado pelo `applyDump` do CLI sobre um banco `node:sqlite` temporário, e dump do CLI aplicado pelo `importDump` do web sobre `fake-indexeddb`. `RF-20` (export automático a cada migração para o arquivo morto) fica fora: a migração ainda não existe no web e entra junto da feature do arquivo morto.
- Consequência: o ciclo fica fechado nas duas superfícies — um arquivo do web abre no CLI e um do CLI abre no web — e a segunda importação do mesmo arquivo devolve `written: 0` e não duplica item, o que torna a idempotência visível na tela.
- Consequência: o export fica disponível mesmo com o banco fora do contrato, e a tela de falha do boot deixa de ser só um beco sem saída.
- Alternativa rejeitada: o web importar `apps/cli` — o CLI é publicado no npm com escopo próprio, o web não tem build que o alcance e o `architecture.test.ts` barra dependência de runtime nova (só `react` e `react-dom`).
- Alternativa rejeitada: escrever o leitor no `packages/core` — o `AGENTS.md` proíbe API de Node/browser no core, há um teste que varre `packages/core/src`, e a mensagem pt-BR do codec furaria a varredura de strings do web.
- Alternativa rejeitada: deixar o DOM do download na view — espalharia `Blob`/`URL`/`document` pelas features e faria o teste da tela depender de `URL.createObjectURL`, que o jsdom não implementa.
- Alternativa rejeitada: tratar `RNF-07` como exportar o que der — um banco ilegível produziria um arquivo parcial, que é pior que dizer que não deu.
- Gatilho de revisão: o `schema_version` subir para 2 (a escada deixa de ser vazia), o `RF-20`/migração para o arquivo morto entrar no web, ou o sync entre dispositivos virar escopo — aí a regra aditiva por desenho volta à mesa.
